## Overview

## Critical Fixes

### 1. ✅ Missing numpy import in logger.py
**Issue:** `src/utils/logger.py` line 112 used `np.argmax()` without importing numpy, causing `NameError` when `MetricsTracker.get_best_epoch()` is called.

**Fix:** Added `import numpy as np` to the imports section.

**Files Modified:**
- `src/utils/logger.py`

---

### 2. ✅ Loss functions not integrated
**Issue:** FocalLoss and WeightedCrossEntropyLoss were implemented but never used. Models hardcoded `nn.CrossEntropyLoss()` regardless of config settings, making `loss_type`, `focal_loss_alpha`, and `focal_loss_gamma` config parameters useless.

**Fix:** 
- Added `loss_fn` parameter to both `PhoBERTEmotionClassifier` and `BamiBERTEmotionClassifier` constructors
- Models now accept and use custom loss functions
- Created `create_loss_function()` factory method in `model_factory.py` that instantiates the correct loss based on config
- Updated `train.py` to:
  - Compute class weights when using weighted_ce
  - Create loss function before model creation
  - Pass loss function to model via factory

**Files Modified:**
- `src/models/phobert_emotion.py`
- `src/models/bamibert_emotion.py`
- `src/models/model_factory.py`
- `scripts/train.py`

**Config Parameters Now Functional:**
- `loss_type`: "cross_entropy", "focal_loss", or "weighted_ce"
- `focal_loss_alpha`: Alpha parameter for FocalLoss
- `focal_loss_gamma`: Gamma parameter for FocalLoss (default: 2.0)

## Architecture Improvements

### Loss Function Flow
```
Config (loss_type) 
    → create_loss_function() 
        → FocalLoss / WeightedCrossEntropyLoss / CrossEntropyLoss
            → passed to create_model()
                → stored in model.loss_fn
                    → used in model.forward()
```

### Data Loading Flow (Updated)
```
Load Dataset
    → Validate splits and keys
    → Validate data integrity
        → Compute class weights (if weighted_ce)
            → Create loss function
                → Create model with loss function
                    → Create dataloaders
```

## Breaking Changes
**None** - All changes are backward compatible. Models default to `CrossEntropyLoss` if no loss function is provided.
